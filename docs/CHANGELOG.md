# 自动更新日志

`changelog` 是主题的构建时组件。正文放一个 shortcode，文章增加、改名、改日期或移除后，下次 Hugo 构建就会重新生成月份、数量与文章链接，无需复制文章标题。

## 接入

在已有 `content/changelog/index.md` 或 `_index.md` 的正文独立放置：

```markdown
{{< changelog sections="posts" >}}
```

完整可复制页面与实际效果见教程 15。普通文章页复用现有右侧目录／移动目录；`_index.md` 继续使用主题 changelog 列表布局。没有 shortcode 的旧页面保持原有渲染。

## 参数与数据契约

| 项目 | 规则 |
| --- | --- |
| 必填参数 | 无。`{{< changelog >}}` 默认读取 `posts`。 |
| `sections` | 逗号分隔的顶层栏目名，例如 `posts,notes`；自动去重、去除两端空格。包含各栏目下的嵌套文章。不是分类名、URL 或业务词。 |
| 语言 | 只读取调用页面所属语言的 `Site.RegularPages`，不会重复列出其他语言的翻译。 |
| 日期 | 按 Hugo `.Date`（默认来自 front matter 的 `date`）归入 `YYYY-MM`，月份和文章均倒序。遵循宿主日期解析／时区配置，不改写文章日期。 |
| 修改日期 | `lastmod` 不作为新增日期，不把旧文章修改伪装成新文章，也不推测历史改动。 |
| 收录范围 | 只收录可链接的普通页面，排除调用页自身、草稿、无有效日期、未来文章日期／发布日期、已过期内容；即使构建时启用草稿、未来或过期内容，仍不收录这些页面。Hugo 已从集合排除的页面也不会重新纳入。 |
| 单篇排除 | 被收录文章的 front matter 写 `changelog: false`；适合位于 posts 下的关于页等非文章内容。它只影响本组件。 |
| 数量 | 从同一份过滤后的文章集合统计，包含全部符合条件的文章，无分页截断。无文章的月份不展示。 |
| 无内容／栏目不存在 | 显示本地化的“暂无已发布的文章”，不输出虚假的月份或数量。拼错栏目名也会为空，请核对目录。 |
| 非法栏目参数 | 使用具名参数；空字符串、含空项、路径分隔符、`.` 或 `..` 时构建报错并给出调用位置。 |
| 嵌套与次数 | 单标签、无 Inner；每页一次，独立放在页面正文中，不嵌套在其他 shortcode、列表、段落或代码块内。 |
| 标题与锚点 | 每月输出 H2 和 `#YYYY-MM` 锚点；不要在同页手写相同 ID。复用主题自动目录，站点无需维护第二份月份清单。 |
| 浏览与交互 | 原生文章链接，全部列表直接可见。无额外 JavaScript 或第三方接口；禁用脚本也能阅读和跳转。 |

主题只按已有元数据整理记录，不生成“本月专题”“站点升级原因”等作者观点。界面文案提供简体中文、繁体中文与英文，配色复用主题变量。

## 迁移手写日志

1. 保留原页面路径和 front matter，用 shortcode 替换人工维护的月份、篇数、文章标题清单。
2. 将建站、版本发布、功能调整等文字保留在独立的“站点与主题更新”标题下。月份已由组件生成时，手写说明使用更具体的日期／事件标题，避免重复锚点。
3. 老的 `#YYYY-MM` 链接在该月仍有文章时继续有效；没有文章的历史月份需手写保留其标题或显式锚点。具体事件的旧锚点也应保留。
4. 核对 `date` 与排除页面；自动统计可能与已过时的手写数量不同，应以实际文章为准。
5. 发布前构建并检查真实日志页。自动化随站点构建生效，不是后台定时任务；未来文章到期后仍需要构建部署才能上线。

支持多个栏目：

```markdown
{{< changelog sections="posts,notes" >}}
```

从日志排除非文章页面：

```yaml
title: 关于我
changelog: false
```

实现使用 Hugo 的 [GroupByDate](https://gohugo.io/methods/pages/groupbydate/) 构建月份关系，主题统一承担布局、日期、统计与链接；宿主无需公共 CSS/JS 或模板覆盖。
