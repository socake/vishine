# HTML 图表嵌入

已有可独立打开的 HTML 图表时，用 `html-embed` 直接嵌入文档。SVG 和 HTML 文字由浏览器绘制，避免位图截图缩放带来的细节损失。宿主维护图表文件和事实内容，主题提供边框、标题、滚动区域、配色接入和原页面入口；不把整个 HTML 的 CSS/JS 注入博客页面。

简单流程可以直接写 Mermaid；独立 `.svg` 文件用普通 Markdown 图片。`html-embed` 的 `src` 只接受 `.html`，无需为普通 SVG 另造包装页。HTML 内若原本就是位图，嵌入不会把它转换成矢量。

将文件放在宿主 `static/diagrams/flow.html`，正文写：

```markdown
{{< html-embed src="/diagrams/flow.html" title="请求处理流程" fit="width" height=480 minWidth=960 >}}
```

| 参数 | 必填 / 默认 | 契约 |
| --- | --- | --- |
| src | 必填 | 站点 static 下的本地 `.html` URL；可带前导 `/`，相对站点根解析并兼容 baseURL 子路径。不能包含查询、片段、外部域、协议或 `..` |
| title | 必填 | 可读标题，同时作为 iframe 的可访问名称 |
| height | 480 | iframe 初始高度，整数 160–1600px；普通 page 模式固定为此值。Archify 加载后按自然内容高度调整，上限 1600px，缩窄后可以低于 160px，避免多余空白 |
| minWidth | 0 | 细节视图的最小宽度，整数 0–2400px；0 不设宽度下限，也不显示尺寸切换按钮 |
| fit | 见下文 | `width` 适应正文宽度；`scroll` 按 minWidth 保留宽度下限。未填写时，有非零 minWidth 的旧调用保持 scroll，其余使用 width |
| mode | page | `page` 原样打开文件；`archify` 使用该生成器的 `embed=1` 模式并传入 `theme=light/dark` |
| surface | Archify 为 theme；page 为 source | `theme` 将同源 Archify 的中性画布、文字、连线与边界变量映射到当前博客配色；`source` 保留图表原配色。普通 page 只能使用 source，非法组合构建失败 |

这是单标签组件，不嵌套正文。无参数、非法地址或越界尺寸导致构建失败。文件是否存在和响应正常由宿主负责，浏览器无法加载 iframe 时仍可使用始终显示的原页面链接；不会伪造加载成功状态。主题不访问远端 HTML，也不自动把位图转换成矢量。

只嵌入宿主自己维护和信任的 HTML。本地 HTML 与站点处于同一来源，可运行自身脚本；组件不作为不可信用户代码的隔离沙箱。图表若使用外部字体、脚本等资源，它们的可用性仍由图表负责。

## Archify 图表

```markdown
{{< html-embed src="/diagrams/architecture.html" title="系统架构" mode="archify" fit="width" height=426 minWidth=1138 >}}
```

此模式隐藏 Archify 独立页的外围工具栏，保留矢量图；完整探索工具在“打开完整图表”的独立页中使用。脚本观察同源图表的自然内容高度，切换阅读宽度时同步调整，避免裁掉底部；不满足同源、嵌入模式或脚本不可用时保留 height。超过 1600px 的图表需打开完整页面。博客暖纸 / 纯白对应 light，暗色对应 dark；配色变化通过重新加载 iframe 生效，因此图内临时状态也会重置。普通 page 模式的配色由图表自己负责。

Archify 默认使用 `surface="theme"`：在其根元素确认 `data-embed="true"` 后，主题将 `--bg` / `--panel` / `--mask`、`--text*`、`--grid` / `--panel-border` / `--lane-*` / `--arrow` 等中性 CSS 变量同步为博客的表面、正文和边界色。节点类别色、布局、文字事实和完整独立页保持由图表维护。暖纸和纯白之间只更新变量；深浅切换仍重新加载。图表不支持这些变量时不会自动重写其 CSS，无脚本时保留源图配色。

需要保留旧配色，显式添加 `surface="source"`；旧的 `mode="archify"` 调用会采用新的中性表面，这是本次外观升级的默认变化。接口只适用于宿主信任的同源 Archify 文件，不承诺接管任意 HTML 或跨域图表。教程 14 展示同一份图表在 theme / source 两种表面下的可复制用法与实际效果。

组件保留原生 lazy loading；无主题脚本时仍可显示 iframe 和打开链接，Archify 使用站点默认配色。内部图表若自身依赖脚本，则遵循该图表的无脚本行为。打印只保留标题和原页面 URL，不承诺跨浏览器打印 iframe 内容。

## 自适应宽度与细节视图

新接入推荐显式使用 `fit="width"`：图表先完整适应正文，切换阅读宽度和手机横竖屏时随容器变化。配合非零 `minWidth`，较窄时显示“放大细节”按钮，点击后按可读宽度展示，并可用“适应宽度”切回；只有细节视图溢出时提示横向滚动，Tab 可聚焦滚动区域，左右方向键可滚动。切换不重新加载 iframe、不移动焦点，回到适应宽度时清零横向滚动位置；刷新后恢复作者指定的 fit。正文宽于 minWidth 时无需放大，不显示多余按钮。

兼容旧调用：只写 `minWidth=1138` 仍默认保留宽度下限。希望默认完整显示，需要同时增加 `fit="width"`；仅设置 `width:100%` 无法覆盖最小宽度。无脚本时按作者配置显示，尺寸切换按钮隐藏，原页面链接始终可用。

矢量缩放能保留清晰边缘，但无法让宽幅密集图在手机上同时保持完整全图和原字号；先看全图，再用细节视图阅读小字。图内 SVG／HTML 也必须支持容器宽度变化；本组件不会重排任意固定坐标图的节点，不通过 transform 缩放整篇页面。普通 page 模式只调整 iframe 宽度，高度仍由 height 决定。iframe 内的交互和快捷键由图表自己定义。

## 接入与验收

1. 先确认预览实际使用的主题目录与版本；主题更新后，宿主 submodule 也要采用对应提交，避免本地和发布使用不同组件。
2. 先独立打开图表，再在真实文章中嵌入。`src` 不带 `static/`；部署到子路径时由主题补全 baseURL 路径，不手写部署前缀。
3. 检查适应宽度时全图完整，按文字可读尺寸选择细节视图的 `minWidth`。桌面、320/390px 窄屏都检查放大／切回、整页不横向溢出、图表底部完整、局部滚动与键盘可用；检查三套配色及完整页面入口。
4. 使用 Archify 时切换宽窄阅读和配色，检查高度重算；使用普通 page 模式时分别确认指定高度和图表自身配色。源 HTML 缺失不会导致构建报错，必须确认发布后的实际 URL 可访问。

实际源码与渲染示例：[教程 14](https://socake.github.io/vishine/tutorial/docs/14-reading-search/#直接嵌入-html-图表)。`check-component-docs.py` 将实际渲染的 Markdown 源码和演示 HTML 放入独立宿主重新构建，检查子路径、懒加载和可访问名称；它不替代上述浏览器验收。
